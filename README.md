# 한국주식 대시보드

코스피·코스닥 지수, 시장 온도계, 외국인·기관 수급, 종목 순위, 업종별 등락을
한 화면에서 보는 정적 사이트. GitHub Pages로 배포된다.

## 무엇이 먼저 보이는가

화면은 "오늘 중요한 것"이 위에서부터 순서대로 오도록 짰다.

1. **지수 스탯 타일** — 코스피·코스닥·코스피200
2. **시장 온도계** — 상승/보합/하락 종목 수 누적 막대(코스피·코스닥 각각) + 상한가·하한가 개수.
   지수 숫자만으로는 안 보이는 체감 장세가 여기서 드러난다.
3. **종목 순위** — 상승률·하락률·거래대금·거래량·시가총액, 그리고 **수급**
4. **업종별 등락 히트맵** — 79개 업종

표에서 종목을 누르면 **종목 상세**가 열린다. 주소에 `#005930` 이 붙어 링크로 공유되고
뒤로가기로 닫힌다.

- **주가 흐름** — 캔들차트 + 아래에 거래량 히스토그램(1개월/3개월/6개월/전체, 선 차트로
  전환 가능). 십자선을 올리면 그날의 시·고·저·종가와 거래량이 뜬다.
- **호가잔량** — 매수·매도 대기 물량의 총합 비율과 5호가 단계별 잔량
- **52주 위치** — 52주 최저~최고 사이에서 현재가가 어디쯤인지
- **지표** — 전일·시가·고가·저가·거래량·대금·시총·외인소진율·52주 최고/최저·
  PER·EPS·추정PER·추정EPS·PBR·BPS·배당수익률·주당배당금
- **수급** — 외국인·기관·개인 순매수와 연속일수, 외국인 지분율
- **소속 테마와 비중** — 이 종목이 속한 테마를 등락률 높은 순으로 늘어놓고, 고른 테마의
  구성종목 표에서 **시총 비중**과 **거래대금 비중**을 계산해 보여준다. 지금 보는 종목의
  행을 강조한다. (삼성전자는 31개 테마에 속하고, 그중 "소캠(SOCAMM)" 안에서 시총 비중
  54.8%를 차지하는 식이다.)

### 수급 탭

주체 × 방향 × 연속일수를 조합해 12가지를 본다.

| | |
|---|---|
| 주체 | 외국인 / 기관 |
| 방향 | 순매수 / 순매도 |
| 연속 | 당일 / 3일 연속 / 7일 연속 |

"3일 연속"은 **3일 이상** 연속을 뜻하고, 정렬은 그 연속 기간의 **누적 순매수 금액** 순이다
(순매도는 누적 순매도가 큰 종목이 위로 온다). 연속일수 배지의 `+`는 확보한 과거 데이터
전체가 같은 방향이라 실제로는 더 길 수 있다는 표시다.

표는 열마다 강약을 다르게 준다. 등락률·거래대금·순매수는 크고 진하게, 전일대비·거래량·
시가총액은 뒤로 물렸다. 등락률 칸에는 강도 막대가 붙는데, **눈금은 ±30%(가격제한폭) 고정**이라
필터를 바꿔도 막대 길이가 흔들리지 않는다. 상한가·하한가는 채운 배지로 표시한다.

## 어떻게 도는가

브라우저에서 증권 API를 직접 부르면 CORS에 막힌다. 그래서 **수집은 GitHub Actions(서버)가
하고, 페이지는 구워진 JSON만 읽는다.**

```
GitHub Actions (5분마다)
   └ node scripts/fetch.js        네이버 금융 공개 JSON 엔드포인트 수집
        └ public/data/*.json      정적 데이터로 굽기
             └ actions/deploy-pages   Pages로 배포 (저장소에 커밋하지 않음)
                  └ 브라우저가 data/*.json 만 fetch
```

- API 키가 필요 없다. 따라서 노출될 비밀도 없다.
- 데이터를 저장소에 커밋하지 않으므로 5분 주기여도 커밋 히스토리가 더러워지지 않는다.
- `public/data/*.json`은 `.gitignore` 대상이다. 로컬에서 보려면 직접 한 번 생성해야 한다.

## 로컬에서 보기

```bash
node scripts/fetch.js                 # public/data/{market,stocks}.json 생성 (약 6초)
npx serve public                      # 또는 아무 정적 서버
```

`file://`로 열면 `fetch`가 막히므로 반드시 정적 서버로 띄운다.

## 갱신 주기

`.github/workflows/update.yml`의 cron은 UTC 기준이다(KST = UTC+9).

| cron | 실제 시각(KST) | 용도 |
|---|---|---|
| `*/5 0-6 * * 1-5` | 평일 09:00~15:55, 5분 간격 | 장중 |
| `10 7 * * 1-5` | 평일 16:10 | 마감 확정치 |

GitHub Actions의 cron은 정시성이 보장되지 않아 **몇 분 늦게 실행될 수 있다.** 화면 우상단에
표시되는 "기준 시각"이 실제 수집 시각이다. 실시간 호가가 아니다.

> **저장소는 public이어야 한다.** 이 주기면 월 2,000분 안팎을 쓰는데, public 저장소는
> Actions가 무제한 무료이고 private은 무료 한도(월 2,000분)를 넘겨 과금된다.

## 데이터

| 파일 | 내용 |
|---|---|
| `public/data/market.json` | 지수 3종, 업종 79개 등락, 시장 폭(상승/보합/하락·상한가·하한가), 수집 시각 |
| `public/data/stocks.json` | 전 종목 약 4,300건 (주식·ETF·ETN) |
| `public/data/flows.json` | 거래대금 상위 500종목의 외국인·기관·개인 순매수, 연속 순매수/순매도 일수와 누적 금액, 외국인 지분율 |
| `public/data/themes.json` | 테마 266개와 각 구성종목 코드 (6,500쌍). 시세·시총은 싣지 않고 화면에서 `stocks.json` 과 합친다 |
| `public/data/stock/{code}.json` | 종목별 지표 18종 + 일봉 약 170일. 클릭할 때만 받도록 종목별 파일로 쪼갰다 (약 730개, 6MB) |

`stocks.json`은 크기를 줄이려고 객체 대신 `cols` 헤더 + 배열 행으로 싣는다.

```
cols: code, name, market, type, price, change, rate, volume, value, cap
      market 0=코스피 1=코스닥 · type 0=종목 1=ETF 2=ETN
      price·change 원 · rate % · volume 주 · value·cap 원
```

주의할 점 두 가지.

- 네이버 응답의 `marketValue`/`accumulatedTradingValue` 문자열은 각각 억원·백만원 단위지만
  `*Raw` 필드는 **원 단위**다. `scripts/fetch.js`는 Raw를 우선 쓰고, 없을 때만 환산한다.
- 수급 API(`/api/stock/{code}/trend`)는 순매수 **수량(주)** 만 준다. 화면의 순매수 금액은
  수량 × 종가로 추정한 값이며 실제 체결 평균가 기준이 아니다. 종목마다 요청이 하나씩
  필요해 전 종목은 무리라 **거래대금 상위 500종목**만 수집한다(동시 8개, 약 6초). 따라서
  수급 탭의 순위는 "거래대금 상위 500종목 중"의 순위다 — 화면에도 그렇게 밝혀 둔다.
- 같은 응답이 **최근 10영업일치를 최신순으로** 함께 준다. 연속 순매수/순매도 일수는 추가
  요청 없이 이 배열만으로 센다. 대신 **연속일수는 10에서 잘린다** — 10일 연속이면 그보다
  길어도 알 수 없어 배지에 `+`를 붙인다. 신규 상장 등으로 응답이 5~6일치뿐인 종목도 있어
  (500종목 중 2개), 그런 종목은 7일 연속 판정 자체가 불가능하다.

- 상한가·하한가는 등락률로 어림잡지 않고 원본이 주는 `compareToPreviousPrice.name`
  (`UPPER_LIMIT` / `LOWER_LIMIT`) 플래그를 그대로 쓴다.
- 종목 상세(지표·차트)는 종목마다 요청이 둘이라 전 종목을 받지 않는다. **거래대금 상위
  500 + 시총 상위 200 + 상승률 상위 200 + 하락률 상위 200의 합집합**(약 730종목)만
  받는다. 순위표에서 눌릴 만한 종목은 사실상 다 들어오지만, 검색으로 그 밖의 종목을 열면
  차트·지표 자리에 "대상 밖" 안내가 뜬다.

전체 수집은 약 15초다. 테마·상세·수급이 서로 병렬로 돌아, 상세를 추가해도 시간이 거의
늘지 않았다.

### 매수/매도량에 관해

**국내 공개 데이터에는 일별 "매수 체결량 / 매도 체결량" 분리가 없다.** 증권사 유료 API
영역이다. 차트 아래 거래량 막대를 상승/하락으로 칠하는 것은 차트 도구들의 표준 관행이고,
이 색은 *그날 종가가 시가보다 올랐는지*를 뜻할 뿐 매수·매도를 나눈 값이 아니다. 화면에도
그렇게 적어 두었다.

실제 매수·매도에 가장 가까운 것은 둘이다.

| | 무엇인가 | 한계 |
|---|---|---|
| **호가잔량** (`/askingPrice`) | 지금 대기 중인 매수·매도 주문량 | 체결량이 아니라 대기량. 장 마감 후에는 마감 시점 스냅샷으로 굳는다 |
| **투자자별 순매수** (`/trend`) | 외국인·기관·개인이 실제로 순매수/순매도한 수량 | 하루 단위 순액이라 장중 흐름은 안 보인다. 최근 10영업일치 |

## 색

등락 표현은 발산형(diverging) 인코딩이다. 국내 관례대로 **상승=빨강 / 하락=파랑**,
보합은 중립 회색. 파랑 arm은 레퍼런스 blue 램프를 그대로 쓰고, 빨강 arm은 같은 명도
(OKLCH L 0.812 / 0.623 / 0.480)에 레퍼런스 red 색상을 얹어 계산했다 — 두 팔의 밝기가
대칭이라 부호만 다른 같은 크기가 같은 무게로 보인다.

색만으로 뜻이 전달되지 않도록 모든 등락 표기에 ▲▼ 글리프가 붙고, 히트맵에는 척도 범례와
동등한 **표 보기**가 함께 있다. 히트맵 셀 안 텍스트는 모든 구간에서 5:1 이상 대비를 낸다.

수치는 지연·오류가 있을 수 있고, 정보 제공 목적이며 투자 권유가 아니다.
